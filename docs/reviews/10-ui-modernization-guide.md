# Review 10: UI modernization guide (owner, 2026-10-14)

The owner supplied an "EAM & Inspection App — AI Implementation & Modernization Guide" as styling guidance for the
web app. This file records it in condensed form and says how each point maps to the board. It is advisor-level text:
ADRs and `docs/blueprint/01-decisions.md` win where they disagree (see "When documents disagree" in `AGENTS.md`).

## Persona and directives

Senior UI/UX systems architect for industrial enterprise tools (oil and gas, heavy infrastructure, mining, quality
compliance). Dense but uncluttered, WCAG 2.2 AA, a quiet work tool: no whimsical animation, no oversized empty space,
no chunky touch cards on desktop. Build on `packages/ui/src/tokens/tokens.css` and `config/terms/en-AU/*.json`; never
replace them with hard-coded values. Agents keep discretion over whether a component is new, refactored or left alone.

## Where the guide and the ADRs disagree (ADRs win)

- **Nav groups.** The guide puts Notifications and Approvals Inbox under Work and assets, Documents under Field and
  execution, and Global search and System audit log under Insight. ADR 0018 makes Documents and transmittals its own
  top-level group, puts notifications and global search in the header as utilities, and puts audit under Settings.
  DESIGN-06 follows ADR 0018. The guide's item list inside each group is still useful for later module nav entries.
- **Hairline borders and contrast.** `#e5e5e5` on white is 1.26:1 and `#d4d4d4` is 1.48:1. That is fine for a
  decorative panel edge, but WCAG 1.4.11 needs 3:1 for boundaries that identify a control. Inputs and checkboxes keep
  `--border-strong` (`#737373`, 4.7:1); only panels and table rules use the hairline.
- **Tinted chips in high contrast.** The outdoor high-contrast theme keeps solid chips (sun glare washes out tints).
- **"Customise per tenant" brand colours** must pass the existing `isAccessibleAccent` check (DESIGN-05).

## Data the Home page needs that P0 does not have

SLA hours, ITPs, NCRs, RFIs, punch items, expiring calibrations and certificates come from R1/P1 modules
(inspections, issues, equipment, eligibility). In P0 only the approvals inbox (APPROVALS-06) and the audit activity
feed (AUDIT-04) exist, so DESIGN-12 ships with those two sources and a provider interface that R1 modules plug into.

## Owner answers (2026-10-14)

- Nav groups: keep ADR 0018. Home / My Work: build alongside R1. Mobile bottom bar: field app; the web app keeps the
  drawer.
- **Added:** each user chooses whether records open in a side panel (the Blade, default) or as a full detail page,
  on the "My display preferences" page (`/settings/design/preferences`). Both modes render the same detail body, so
  modules build it once. → DESIGN-13.
- **Added (branding):** the header's top-left shows the company name followed by "AIP" (DESIGN-14). Tenant admins
  match their company colours by choosing a preset palette or entering custom accent and header colours, each
  contrast-checked, and can let users choose their own colours (on by default). Users choose from the presets only
  (DESIGN-05, DESIGN-13).
- **Caution on red, green and amber accents:** they share hues with the danger, success and warning status colours,
  so a red primary button can look like a delete button. Status always carries an icon and text, and danger buttons
  keep their icon, so meaning never depends on colour alone. Kaefer red stays allowed.
