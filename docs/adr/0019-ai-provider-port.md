# ADR 0019: AI provider port with two adapters; Bedrock Sydney is the default

- **Status:** accepted (owner, 2026-10-10)
- **Date:** 2026-10-10
- **Affects:** ai_gov, ai_assistant, docs/internal; resolves OPEN-QUESTIONS 4

## Context

ADR 0007's stack notes say "direct model vendor API", while the `ai_gov` module assumes Bedrock in Sydney with zero
retention. The owner wants both, and Bedrock Sydney if only one is built.

## Decision

1. One `AiProvider` port, with two adapters: `bedrock` (AWS Bedrock, region ap-southeast-2) and `anthropic` (the
   vendor's direct API). Callers never know which one runs.
2. **Bedrock Sydney is the default** and the first adapter built. The direct adapter is off by default, switched on per
   tenant by an operator, gated by an entitlement, and listed as a sub-processor because content leaves AWS Sydney.
3. Budgets, the kill switch and logging in `ai_gov` apply identically to both adapters.
4. **Verify before claiming Australian residency.** Some Bedrock models are served through cross-region inference
   profiles that may route outside Sydney. The adapter's build task records which model and profile are used and
   whether processing stays in Australia; the sub-processor list and customer wording follow what is verified.

## Consequences

`ai_gov` tasks (generated by PLAN-R1 when that phase is planned) implement the port, then the Bedrock adapter, then
the direct adapter. Zero-retention settings are used where the provider supports them.
