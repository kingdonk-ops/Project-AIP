### Tech stack advisor

Continue AIP (FastAPI/SQLAlchemy/Postgres + React/Vite/shadcn) rather than rebuilding in TypeScript. Forty-eight shipped phases cover your hardest domain logic: asset ltree, review lifecycle, hold points, the RSW completion gate and certificate hard-block. The TS rebuild buys little here, because the frontend is already TypeScript and the real risks are compliance, offline sync and tenancy, not the backend language. Rebuilding would cost roughly 6-12 months of parity work before Kaefer sees anything new. Python also has the best libraries for the heavy parts: IfcOpenShell, pyHanko, OCR and WeasyPrint. Keep one language in the API and sidecar. Buy identity (WorkOS), host on ECS Fargate in Sydney, and budget about AUD 2.5-4k/month at 500-5,000 users (pooled), excluding Vanta/Drata and IRAP assessor fees.

Keep the frontend contract stable by generating TypeScript types and a client from FastAPI's OpenAPI schema (openapi-typescript or orval), so you get end-to-end type safety without a rewrite. Revisit only if you hire a TS-only team, and even then refactor module by module, not wholesale.
- **[high] Buy identity: WorkOS for SAML/SCIM, keep local auth thin**: Use WorkOS SSO + Directory Sync (about USD 125/connection/month each for SSO and SCIM; confirm current pricing) and verify the JWT in FastAPI (authlib/PyJWT). Check WorkOS's data residency and IRAP position before signing; Keycloak self-hosted on ECS is the fallback for siloed IRAP tenants.
- **[high] Harden tenancy before adding modules**: Enforce RLS via a per-request SET LOCAL app.tenant_id on every pooled connection, and add the Testcontainers isolation and IDOR tests early. Verify AIP's current models actually carry tenant_id everywhere, since a single-customer app often does not. Use one codebase with a siloed-deployment option (own RDS, KMS key, bucket) for IRAP and mining clients.

- **[high] Offline field app: PWA first, native later**: Build the field app as a React PWA with IndexedDB (Dexie) and a service worker, using your designed cursor-pull/idempotent-push protocol and the existing sync_version column. Offline reliability on LNG and mining sites is the highest delivery risk, so run an offline-capture pilot with Kaefer inspectors early. - **[medium] Form logic sandbox: no eval, declarative expressions**: The owner's 'Java validation' wish should be satisfied with json-logic or CEL (cel-python server-side, cel-js in the client) rather than user-supplied code. - **[medium] Search, jobs, real-time: stay inside Postgres where you can**: Use Postgres FTS plus pgvector (RDS supports both), applying permission filters in the query. For jobs, use arq (Redis) or Procrastinate (Postgres-backed, fewer moving parts) with job state in Postgres; skip Celery. For real-time, use SSE or WebSockets from FastAPI with Redis pub/sub, which is enough for feeds and sync chips. Add OpenSearch only if FTS proves inadequate.
- **[medium] IFC/CAD sidecar and e-signature scope**: IFC via IfcOpenShell with web-ifc/That Open Components or xeokit for viewing; CAD/DWG via the Autodesk Platform Services API or ODA, since open DWG conversion is poor. Defer BIM until a customer pays. For external signatures use a provider abstraction over DocuSign or Adobe Sign, and keep in-app PAdES for internal sign-off.
- **[medium] Hosting path and compliance sequencing**: Coolify for dev/demo only. Build Terraform/CDK for ECS Fargate, RDS Postgres Multi-AZ, ElastiCache, S3 with Object Lock, CloudFront and WAF in ap-southeast-2 now, so the audited environment is the production one. Start Vanta or Drata for ISO 27001/SOC 2 readiness, and engage an IRAP assessor only once a government customer needs it. Use Bedrock Sydney for AI and transcription (Transcribe), which suits the governance module.

### Security advisor

The design intent is strong: RLS on every table, a single authorisation layer, quarantined uploads, hash-chained audit and an AI register. The risk is that these controls are specified but not yet proven in AIP, which was built 48 phases before the security programme existed. Highest-risk areas are: tenancy in a pooled database serving mining and government clients; magic-link/PIN access for field and external users; the upload and conversion pipeline; legal records that must be provably tamper-evident; and AI/voice features handling recordings and personal data. For Kaefer/Rio Tinto, expect questions on residency, offboarding, MFA, and evidence. Prioritise tenancy verification, identity lifecycle, and the pipeline before adding modules. Pursue SOC 2 Type I and ISO 27001 first, with IRAP later and a siloed option for government.

- **[high] Prove tenant isolation before adding modules**: Audit every AIP table for tenant_id and enable FORCE ROW LEVEL SECURITY. Connect with a non-owner, non-BYPASSRLS role and set app.tenant_id via SET LOCAL inside each transaction, failing closed if unset. Add Testcontainers cross-tenant tests, generated IDOR tests per endpoint, and checks on Redis keys, S3 prefixes, search indexes and background jobs.
- **[high] One authorisation layer, deny by default, server-side**: Evaluate permissions in a single policy service combining role, project, team, discipline and asset-subtree scope, then enforce it in RLS or query filters rather than post-filtering. Generate a permission-matrix test from the catalogue so every route and every role is covered. Log permission overrides and role changes to the audit chain, and require approval for admin-level grants.
- **[high] Constrain field and external credentials**: Treat magic links and PINs as bearer credentials: single use, short TTL, hashed, device-bound, scoped to named projects and modules, with POST confirmation so mail scanners cannot burn them. Serve the portal from a separate origin with its own cookies, CSP and WAF rate limits. Make SCIM deprovisioning revoke sessions, tokens, API keys and links, and measure and test the revocation time.
- **[high] Harden the file and conversion pipeline**: Make quarantine-scan-validate-release the only route to tenant storage, covering uploads, inbound email, webhooks and offline-deferred media. Run IFC, CAD, OCR and PDF render in network-isolated, non-root containers with CPU, memory, time and decompression limits, no egress, and a read-only filesystem. Strip or gate EXIF GPS, block active content in PDFs and Office files, and never render user HTML with network access in the report engine.
- **[high] Make legal records verifiably tamper-evident**: Write audit, signing and diary seals to append-only tables with REVOKE on UPDATE/DELETE for the app role, separate from the migration role. Anchor hash-chain heads to S3 Object Lock in compliance mode, and keep PAdES keys in KMS with restricted use and logging. Ship a verification tool, test chain breaks in CI, and define legal hold versus crypto-shredding precedence so offboarding cannot destroy held records.
- **[high] Gate AI behind a data-flow register**: Default AI off per tenant and feature, with a recorded provider, region, retention and zero-retention setting for each flow. Use Bedrock Sydney for AU clients, redact personal data and commercial rates, and apply permission filters before retrieval. Treat documents, emails and transcripts as untrusted prompt-injection input; give agents read-only tools, no URL fetching, and human confirmation for writes.
- **[medium] Align residency, backups and the Coolify-to-AWS move**: Keep real client data out of Coolify environments; use synthetic data there, and run staging and production on AWS ap-southeast-2 built from IaC. Encrypt with per-tenant KMS keys, replicate backups only within permitted regions, and run quarterly restore tests with recorded RPO/RTO. Document NZ-in-Sydney and later UK/Singapore stacks, including support-access and sub-processor locations.
- **[medium] Secure software pipeline and evidence collection**: Build images once, then scan (SCA, SAST, secrets, container), sign with cosign, generate SBOMs and promote the same artefact. Require reviewed PRs, protected branches, least-privilege CI roles with OIDC to AWS, and no dev tooling or seed scripts in production. Connect Vanta or Drata early so evidence for SOC 2 Type I accrues during the pilot.
- **[medium] Control bulk exfiltration and outbound calls**: Make tenant export and backup export approved, rate-limited, audited admin actions with signed, expiring links and alerts. Use an allowlist and SSRF-safe egress proxy for webhooks, chat and connectors. Add HMAC signing, replay protection, per-client scopes and rate limits for the public API.
- **[medium] Privacy Act, retention and recording consent**: Complete the APP data map and NDB runbook, and set retention per record type with legal hold overriding purge. Mask health and injury data at field level, and record consent before call and meeting recording using jurisdiction rules. Remove personal information from logs and telemetry, and define who can access recordings.

### Architecture & code structure

Continue AIP as a modular monolith: one FastAPI deployable (services/api) split into strict modules, a separate worker process, and a Python sidecar for IFC/CAD/OCR. Each module owns its models, schemas, repository, service, policies, events, and routes in one folder, and exposes only a published interface (api.py) plus domain events. Cross-cutting behaviour (CRUD/register, workflow, forms, rules, permissions, audit, files, notifications, terminology) lives once in a platform/ layer configured by data, not copied into modules. The frontend mirrors this with feature folders consuming a generated OpenAPI client and shared engines (DataTable, FormRenderer, WorkflowBar). Import-linter and ESLint boundaries are enforced in CI, so a typical change touches one module folder plus, at most, one migration.

- **[high] Refactor AIP into the module layout incrementally**: Do not rewrite. Move one existing area per phase (start with inspections and eligibility) into modules/<name>/ with an api.py facade, leaving old import paths as shims until the lint contract passes. Add import-linter in warn mode first, then flip to enforce per module as each is cleaned.
- **[high] Build the tenancy base and isolation tests first**: Put RLS, SET LOCAL app.tenant_id, and the base model mixins in platform/db before extracting more modules. Add the generated isolation and permission-matrix tests against Testcontainers Postgres so every new module inherits them automatically.
- **[high] Extract the workflow and rules engines from existing lifecycles**: AIP's inspection review lifecycle, issues and RSW completion gate already encode state logic; lift them into workflow definitions and rule guards in config/workflows. Keep the existing behaviour as golden tests so the extraction is provably non-breaking before documents, POs and variations adopt it.
- **[high] Introduce the terms dictionary before adding market-specific text**: Replace hard-coded labels with keys now, seeded with Kaefer/Rio defaults in config/terms/en-AU. Generate keys from module manifests and add the lint rule so new modules can't regress; market packs then become data-only changes.
- **[medium] Generate the API client and permission catalogue in CI**: Use openapi-typescript or orval into packages/api-client, and emit the permissions package from module manifests. Fail the pipeline on drift so one backend change updates frontend types without manual edits.
- **[medium] Ship the register factory and DataTable together**: Define a single register config consumed by both the backend router factory and the frontend DataTable/columns, then migrate the simple register modules (staff, vehicles, equipment, consumables, contacts) onto it first. These give the largest line-count reduction and validate the pattern before complex modules.
- **[medium] Keep the sidecar and worker as thin edges**: Define JSON schemas in services/sidecar/contracts and run contract tests in CI; the worker only dispatches to module services and platform/files. This keeps IFC/CAD/OCR replaceable and prevents heavy-processing code leaking into modules.
- **[low] Defer low-value modules behind the scaffold**: Modules like cases, interfaces, prefab, and Last Planner should be added only through tools/scaffold with manifests and feature flags per tenant. This keeps the repo small now and makes later modules a one-folder addition.

### Feature filler

This defines seven account types, a shared user profile, 13 default roles and a module-by-role access matrix for AIP. Access is deny-by-default and scoped by tenant, organisation, project, team and asset subtree. Staff use SSO and SCIM, field and portal users hold narrow bearer credentials, and API clients use OAuth. Role names are tenant-renamable through the terminology dictionary, while internal codes stay stable. The cost_items and cases rows are all 'none' because the owner removed those modules.

- **[high] Generate the permission catalogue and matrix tests from this matrix**: Treat this matrix as the seed for AIP's existing permissions catalogue. Convert each cell (none/view/create/edit/approve/admin) into catalogue permissions, and generate a CI test per role and module against Testcontainers Postgres. Include IDOR cases: a Subcontractor reading another team's record, and a Client Reviewer reading an unshared record. Fail the pipeline when the catalogue and the matrix drift apart.
- **[high] Make roles data, scopes explicit, and separate duties**: Store roles as tenant-renamable data keyed by stable internal codes so Kaefer can rename 'Supervisor' or 'Client Reviewer' without changing behaviour. Always assign roles with a scope (project, team or asset subtree) and an optional validity window. Enforce segregation of duties through the rules engine, for example the person who raises an NCR cannot verify its closure, and the person who signs a diary cannot also seal it.
- **[high] Harden the bearer-credential account types first**: Field PIN, magic-link, portal and subcontractor users are the highest-risk accounts. Make links single-use with POST confirmation, hashed at rest, device-bound, and scoped to named projects and modules. Serve the portal from a separate origin with a shorter session. Add supervisor one-click revocation and automatic expiry at the end of a shift or campaign, and test that SCIM deactivation kills all of them.
- **[high] Keep audit, legal-hold and super-admin permissions outside app admin**: Audit, signing seals, diary seals and legal hold should have their own permission set, with no edit or delete rights even for Tenant Admin. Super Admin access to tenant data should be just-in-time, ticketed, tenant-approved and logged. Give Auditor a time-limited, read-only grant that can be issued to external assessors (SOC 2, ISO 27001, IRAP) with an expiry date.
- **[medium] Resolve the removed modules and per-site optional modules**: The cost_items and cases rows are all 'none' because the owner removed them. Delete them from the catalogue and the nav, and strip the dependent hooks in change, logistics and inventory, or those modules will reference records that no longer exist. For HSE Advanced and the other site-optional modules, add a per-site feature flag that sits in front of the matrix, so a role's permission applies only where the module is switched on.
- **[medium] Add review and offboarding evidence for compliance**: Add a quarterly access-review report listing users, roles, scopes, last login and dormant accounts, with sign-off by the Tenant Admin. Retain it as SOC 2 and ISO 27001 evidence. Combine it with SCIM joiner, mover and leaver events so a role change at the IdP automatically updates scoped assignments. Flag local accounts and long-lived API clients separately for review.

### Page & layout designer

Global frame for AIP: constant app shell (header, nav rail, scope bar, asset tree spine) with four sign-in classes (SSO, email+password+MFA, magic link/PIN, system OAuth). Navigation is configuration-driven: content-type registers appear from config, modules can be disabled per tenant or site, and every label resolves through the terminology dictionary. ### Delivery planner

Because the owner chose a TypeScript rebuild, the 48 AIP phases act as a behavioural specification, not reusable code. AIP's schema, RLS and Alembic migrations carry over. The existing lifecycles (inspection review, hold points, RSW completion gate, certificate hard-block) become golden tests that the NestJS rebuild must pass. Phase 0 builds tenancy, identity, authorisation, terminology, workflow and audit foundations with isolation proof. Phase 1 reaches parity on the Kaefer/Rio Tinto core. Phase 2 adds reports, offline and read-only portal access. Phase 3 covers governance and handover. Phase 4 is later and deferred work. cost_items and cases are removed and excluded from the order.
