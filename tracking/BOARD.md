# Task board

The single source of truth for task status. **Dependencies in this table override the ones written
inside task files** (the development-lead review re-wired several of them; see docs/reviews/07-delivery.md).

- Next ready task: `python3 tools/next_task.py` · all ready tasks: `--all` · validate: `--check`
- Statuses: `todo` · `in-progress` · `review` · `done` · `blocked` · `dropped`
- Tasks in the same wave can run in parallel. Notes saying "convert ... per ADR 0001" mean the spec predates the Python-backend decision:
  translate it with the table in ADR 0001 and mark the file `hand-edited`.
- Scope and ordering come from [ADR 0007](../docs/adr/0007-mvp-scope-and-strangler.md). P1+ tasks are generated by `PLAN-R1`.

**M0 walking skeleton** = waves 0–5: two tenants, Keycloak sign-in, Vite web shell, Projects register,
RLS isolation proven in CI, deployed to the Coolify demo (synthetic data only; AWS staging comes in wave 7).
M0 status: the exit proof (TESTING-09) runs in CI (`e2e-skeleton`) and after each demo deploy; the wave 5
tasks still `todo` below remain before M0 is closed.
