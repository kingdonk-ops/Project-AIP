## Spec

Give the forms module its first tables and API: a tenant admin uploads a form template as JSON, the server lints it against a published JSON Schema contract, the field-type registry and the JSONLogic allow-list, and publishing freezes the revision (hash, trigger) so inspections can pin it (tag: extend).

> **Precondition (cross-module).** The lint calls `validate_guard` and `GuardError` through
> `aip.modules.approvals.api`, exported by APPROVALS-08 (a dependency of this row). Never import
> `aip.modules.approvals.guards.jsonlogic` directly (import-linter `no-deep-module-import`) and never copy the
> evaluator into forms.

> **Out of scope:** the register and detail pages (FORMS-04), option sets and the section library (FORMS-06),
> seed templates (FORMS-05), the answer evaluator (FORMS-02), template retire/archive, `discipline_id`,
> `entity_type_id`, `default_frequency` and `required_competency` (their source tables do not exist in R1),
> calculated fields and repeating sections (no R1 row; see the template contract below).

- **steps**:
  - 1. Scaffold the module with `python3 tools/new_module.py forms` (from `apps/api/aip/modules/_template/`). `manifest.toml`: `id = "forms"`, `depends_on = ["tenancy", "item_types", "approvals", "terms"]`, `permission_namespaces = ["form"]`, permissions `form.view` (view templates and revisions), `form.manage` (upload and edit drafts), `form.publish` (publish a revision), and `[[events]] name = "form.revision_published" version = 1`. `subscribes = []`.
  - 2. **Template contract** `packages/contracts/forms/form-template.schema.json` (JSON Schema Draft 2020-12, `$id` `https://aip/contracts/forms/form-template.schema.json`, `additionalProperties: false` everywhere). A revision `schema` is:
    - `{"schemaVersion": 1, "sections": [Section, ...]}`, 1–50 sections.
    - Section: `{key, label, labelKey?, visibleIf?, fields: [Field, ...]}`, 1–100 fields.
    - Field: `{key, type, label, labelKey?, helpKey?, required?: boolean, visibleIf?, requiredIf?, failWhen?, failMessageKey?, options?, unit?, validations?, rules?}`.
      - `key`: `^[a-z][a-z0-9_]{0,62}$`, unique across the whole revision (section and field keys share one namespace).
      - `type`: a key of the field-type registry (`text`, `number`, `decimal`, `date`, `dropdown`, `multi_select`, `measurement`, `boolean`, `photo`, `signature`, `asset_ref`, `user_ref`).
      - `options` (only `dropdown`, `multi_select`): 1–200 `{value, label, labelKey?}`, `value` matching the key pattern.
      - `unit` (only and required for `measurement`): an SI storage unit known to terms.
      - `validations`: `{min?, max?}` (number, decimal, measurement value), `{minLength?, maxLength?}` (text, ≤ 10 000), `{minItems?, maxItems?}` (multi_select, photo). No regex patterns (ReDoS).
      - `rules`: ≤ 20 `{rule, messageKey, message}`; `rule` is JSONLogic that must be truthy for a valid answer.
      - `visibleIf`, `requiredIf`, `failWhen`, `rules[].rule`: JSONLogic over the data shape `{"answers": {<fieldKey>: <value>}, "context": {"kind": ..., "assetId": ..., "projectId": ...}}`.
    - `label` is the tenant's own content (en-AU text). When `labelKey` is set the renderer shows `t(labelKey)` instead; UI chrome never comes from the template.
    - `contract.py` loads the file once (path relative to the repo root, like `aip/platform/http/csv.py` loads `packages/contracts/csv-vectors`) and builds a `Draft202012Validator`.
  - 3. **Migration** `apps/api/migrations/versions/<timestamp>_forms_templates_revisions.py` (one file, `down_revision` = the current head), rendered with `aip.platform.db.templates.render_template`:
    - create `form_templates` with `render_template("tenant_table", table="form_templates", sync=True, columns=...)`: `code text NOT NULL`, `name text NOT NULL`, `kind text NOT NULL`, `status text NOT NULL DEFAULT 'draft'`, `current_revision_id uuid NULL`, `created_by uuid NULL`. Constraints: FK `tenant_id → tenants`, `UNIQUE (id, tenant_id)`, `CHECK (kind IN ('inspection','itp','rfi','permit','test_report'))`, `CHECK (status IN ('draft','active','retired'))`, `CHECK (code ~ '^[a-z][a-z0-9-]{1,62}$')`, unique index `(tenant_id, code) WHERE deleted_at IS NULL`, index `(tenant_id, kind, status)`.
    - create `form_revisions` with `render_template("tenant_table", table="form_revisions", columns=...)`: `template_id uuid NOT NULL`, `revision_no integer NOT NULL`, `status text NOT NULL DEFAULT 'draft'`, `schema jsonb NOT NULL`, `schema_hash text NULL`, `evaluator_version text NULL`, `change_note text NULL`, `published_at timestamptz NULL`, `published_by uuid NULL`, `created_by uuid NULL`. Constraints: composite FK `(template_id, tenant_id) → form_templates (id, tenant_id)`, `UNIQUE (id, tenant_id)`, `UNIQUE (template_id, revision_no)`, `CHECK (status IN ('draft','published','superseded'))`, `CHECK (status = 'draft' OR (schema_hash ~ '^[0-9a-f]{64}$' AND published_at IS NOT NULL))`, partial unique `(template_id) WHERE status = 'draft' AND deleted_at IS NULL` (one open draft), partial unique `(template_id) WHERE status = 'published'` (one current), index `(tenant_id, template_id, status)`.
    - Then add composite FK `(current_revision_id, tenant_id) → form_revisions (id, tenant_id)` on `form_templates`.
    - Freeze trigger `form_revisions_freeze` (`BEFORE UPDATE OR DELETE`): when `OLD.status <> 'draft'`, raise `form revision is frozen` (SQLSTATE `P0001`) if any of `schema`, `schema_hash`, `evaluator_version`, `revision_no`, `template_id`, `published_at`, `published_by`, `deleted_at` changes, on any `DELETE`, or on a status change other than `published → superseded`. Drafts stay editable.
    - Both tables get FORCE RLS with the fail-closed tenant policy and the `aip_app` grants the template renders; `aip_app` loses `DELETE` (soft delete only).
  - 4. `tables.py`: SQLAlchemy Core `Table`s for both. `repository.py`: plain Core queries on the caller's `with_tenant` connection; template updates go through `aip.platform.db.concurrency.update_with_version`.
  - 5. **Lint** `lint.py`: `lint_template(schema: Mapping, *, field_types, known_units) -> list[LintIssue]`, `LintIssue = {path: list[str|int], code, message}`, sorted by path. Codes, in check order:
    - `SCHEMA_INVALID`: any JSON Schema error from `contract.py` (one issue per error, JSON-pointer path). Later checks run only when this passes.
    - `TEMPLATE_TOO_LARGE`: serialised schema > 256 KB or > 500 fields.
    - `DUPLICATE_KEY`: a section or field key used twice.
    - `UNKNOWN_FIELD_TYPE`: `type` not in `aip.modules.item_types.api.field_types()`.
    - `OPTIONS_REQUIRED` / `OPTIONS_NOT_ALLOWED` / `DUPLICATE_OPTION`.
    - `UNIT_REQUIRED` / `UNKNOWN_UNIT`: `unit` missing on a measurement, or `aip.modules.terms.api.to_si(1, unit)` raises `UnknownUnitError`.
    - `VALIDATION_NOT_ALLOWED`: e.g. `minLength` on a `number`; `min > max` → `VALIDATION_RANGE`.
    - `EXPRESSION_INVALID`: `aip.modules.approvals.api.validate_guard(expr)` raises `GuardError`; message = the guard error (`operator not allowed: reduce`).
    - `UNKNOWN_REFERENCE`: a `var` path starting `answers.` whose next segment is not a field key, or a `context.` path other than `kind`, `assetId`, `projectId`.
    - `CONDITION_CYCLE`: a cycle in the graph "field/section → fields its `visibleIf`/`requiredIf` reads" (self-reference included). `failWhen` and `rules` may read their own field and are not in the graph.
  - 6. `service.py` (every operation inside one `with_tenant` transaction; time in UTC, ADR 0025):
    - `upload_template(conn, actor, data)`: lint (any issue → 422 `TEMPLATE_INVALID` with `issues`), insert `form_templates` (status `draft`) and `form_revisions` revision 1 (status `draft`). Duplicate live `code` → 409 `CODE_TAKEN`.
    - `create_draft(conn, actor, template_id, schema?, change_note?)`: next `revision_no`; `schema` omitted → copy of the current published schema. An open draft already exists → 409 `DRAFT_EXISTS`.
    - `replace_draft(conn, actor, revision_id, schema, change_note?)`: lint as above; a non-draft → 409 `REVISION_FROZEN` (checked in the service; the trigger is the backstop).
    - `discard_draft(conn, actor, revision_id)`: sets `deleted_at` on a draft; non-draft → 409 `REVISION_FROZEN`.
    - `publish(conn, actor, revision_id, expected_sync_version?)`: lock the template `FOR UPDATE`; re-lint (the registry may have changed; issues → 422 `TEMPLATE_INVALID`); `schema_hash = sha256` (hex) of canonical JSON (`json.dumps(schema, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`, UTF-8); `evaluator_version = "1"` (FORMS-02 owns the constant; until then the literal); previous `published` revision → `superseded`; this one → `published` with `published_at`/`published_by`; template `current_revision_id` = it, `status` = `active`, `sync_version + 1` via `update_with_version` (mismatched `expected_sync_version` → 409 `VERSION_CONFLICT`); `emit(conn, "form.revision_published", 1, Aggregate("form_template", template_id), payload)` with payload `{templateId, revisionId, revisionNo, code, kind, schemaHash}`.
  - 7. `routes.py`, router under `/api/v1/forms`, mounted with `require_active_tenant`; every route has `requires(...)` (deny by default); strict pydantic bodies (`extra="forbid"`, camelCase):
    - `GET /templates?kind=&status=&q=&limit=` (`form.view`) → list `{id, code, name, kind, status, currentRevisionNo, updatedAt}`.
    - `POST /templates {code, name, kind, schema, changeNote?}` (`form.manage`) → 201 `{template, revision}`.
    - `GET /templates/{id}` (`form.view`) → template plus revision summaries (no schemas).
    - `POST /templates/{id}/revisions {schema?, changeNote?}` (`form.manage`) → 201 draft.
    - `GET /revisions/{revisionId}` (`form.view`) → revision with `schema`, `schemaHash`, `status`.
    - `PUT /revisions/{revisionId} {schema, changeNote?}` (`form.manage`) and `DELETE /revisions/{revisionId}` (`form.manage`, drafts only).
    - `POST /revisions/{revisionId}/publish {expectedSyncVersion?}` (`form.publish`) → 200.
    - `POST /lint {schema}` (`form.manage`) → 200 `{issues}` without writing (the "test before upload" call FORMS-04 uses).
    - Another tenant's id → 404 (RLS hides it; the service raises `NotFoundError`).
  - 8. `api.py` exports `FormsApi` with `get_revision(conn, revision_id) -> FormRevisionOut | None` (frozen revisions only: `published` or `superseded`, so pinned inspections keep working; a draft or unknown id → `None`) and `get_current_revision(conn, template_id) -> FormRevisionOut | None` (the template's `published` revision; `None` for a template with none or `retired`). `FormRevisionOut` carries `id, template_id, template_code, kind, revision_no, status, schema, schema_hash, evaluator_version, published_at`. Also export `lint_template` and `LintIssue` (FORMS-04, FORMS-05 and FORMS-06 reuse them).
  - 9. `events.py` registers the `form.revision_published` v1 pydantic model with `aip.platform.events.register_event`; regenerate `packages/contracts/events/` and `packages/contracts/src/permissions.generated.ts`.
  - 10. `config/terms/en-AU/forms.json`: `forms.permission.view|manage|publish`, `forms.kind.<code>` for the five kinds, `forms.template.status.<code>`, `forms.revision.status.<code>`, and one `forms.lint.<CODE>` message per lint code above (stable codes, en-AU defaults).
- **acceptance**:
  - A tenant admin can upload, lint, revise and publish a template using only the API; a broken template is refused with every issue listed by path and code.
  - A published revision can never change: the service refuses with 409 and the trigger refuses even a raw `UPDATE` as `aip_app`.
  - Publishing writes the revision, the template and exactly one `domain_events` row in one transaction; a forced failure after the revision update leaves all three unchanged.
  - `FormsApi.get_revision` returns superseded revisions (pinned inspections keep their form) and never a draft.
  - No route answers without its permission; another tenant's ids give 404; `import-linter` passes (forms imports approvals, item_types and terms only through their `api.py`).
